System Topology & Thread Isolation

ColonyVision Lab is strictly partitioned into two independent execution environments: the Main UI Thread and a dedicated WebAssembly Web Worker. 

┌─────────────────────────────────────────────── MAIN THREAD (UI & DOM) ───────────────────────────────────────────────┐
│                                                                                                                       │
│   • index.html               (Apple HIG Interface, Canvas Stage, Sliders, Category Histogram)                        │
│   • js/app.js                (UI Controller, Camera Stream, Hover Inspector, CSV/PDF Exporter)                       │
│   • js/db.js                 (IndexedDB Object Store 'experiments', Blobs, Metadata Persistence)                      │
│   • js/vision-client.js      (Worker Supervisor, Promise Wrappers, Timeout Management, Crash Recovery)               │
│                                                                                                                       │
└─────────────────────────────────┬───────────────────────────────────────────────────▲─────────────────────────────────┘

Core Module Specification

Module Role Key Invariants
js/pipeline.js Pure Computer Vision DOM-free. Accepts cv and srcMat. Strict tracker pattern guarantees zero memory leaks.
vision.worker.js Wasm Worker Runtime Imports opencv.js once. Converts ImageBitmap to cv.Mat using OffscreenCanvas.
js/vision-client.js Worker Client Manager Provides async request/response API with 30s timeout safety and transparent worker restart capabilities.
js/db.js Structured Storage Versioned IndexedDB wrapper. Manages Blobs, search indexes, transactions, and full database reset.
js/app.js Application Controller Connects camera, canvas interactions, slider changes, metric recalculations, and library rendering.

OpenCV.js Memory Management (Slide 7 Compliance)

As taught in Dr. Ernesto Lee's CAI 2840 masterclass: "Finish the experiment; free the memory."

In OpenCV.js, any object created with new cv.Mat(), cv.matFromImageData(), or returned by matrix operations allocates memory inside Emscripten's linear WebAssembly heap. If left undeleted, repetitive analysis will rapidly cause an unrecoverable OutOfMemoryError.

ColonyVision solves this through the Tracker Pattern: 

function tracker() {
  const mats = [];
  const T = (m) => (mats.push(m), m);
  T.free = () => {
    for (const m of mats) {
      if (m && typeof m.delete === 'function' && !m.isDeleted()) {
        try { m.delete(); } catch (_) {}
      }
    }
    mats.length = 0;
  };
  return T;
}

// In pipeline execution:
const T = tracker();
try {
  const gray = T(new cv.Mat());
  cv.cvtColor(src, gray, cv.COLOR_RGBA2GRAY);
  // ... all intermediate matrices ...
} finally {
  T.free(); // Guaranteed release on success or failure!
}

Deploying to Netlify

ColonyVision is built as a pure static web application. It requires no build step, no server runtimes, and no external API keys.

  1. Connect the GitHub repository (zoryanaromankiv001-alt/Final) to Netlify.
  2. Leave Build command blank.
  3. Set Publish directory to . (repository root).
  4. Click Deploy site. Netlify reads netlify.toml and immediately configures HTTPS and strict security headers.
